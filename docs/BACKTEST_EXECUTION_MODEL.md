# 백테스트 체결 모델 (Backtest Execution Model)

> 엔진 버전 **0.3.0** (`backend/src/tradingos/backtest/engine.py`, `risk/engine.py`). 2026-11-12 갱신.
> 이 문서는 엔진이 **실제로 하는 일**만 적는다. 구현되지 않은 것은 §9에 "미지원"으로 따로 적는다.
> 모든 결과는 가정에 기반한 가상 시뮬레이션이며 미래 성과를 보장하지 않는다.
> 각 실행 기록의 `execution_model`에 아래 가정이 그대로 저장된다.

## 1. 한 봉의 처리 순서

| 순서 | 처리 | 가격 |
|---|---|---|
| 1 | 펀딩: 이전 봉에서 넘어온 포지션이 펀딩 시각(00/08/16 UTC)을 지나면 정산 | 수량 × 봉 시가 |
| 2 | 직전 봉 종가에서 결정된 **청산 신호** → **시장가 진입** (사전 검사 후) | 봉 시가 ± 슬리피지 |
| 3 | 대기 중인 **지정가 주문**: 취소 또는 체결 판정 | §4 |
| 4 | 봉의 고가/저가로 손절·목표 도달 검사 | §3 |
| 5 | 봉 종가의 신호 → 다음 봉 시장가 진입 예약 또는 지정가 주문 접수 | — |
| 6 | 자산 평가 (실현 자산 + 미실현 손익) | 봉 종가 |

## 2. 시장가 진입

- 신호 봉 i가 닫힌 뒤, **봉 i+1 시가**에 체결. 체결가 = `시가 × (1 ± 슬리피지)` (불리한 방향).
- 마지막 봉의 신호는 실행되지 않는다.
- **주문 전 검사** (하나라도 걸리면 거부하고 사유 기록):

| 사유 | 조건 |
|---|---|
| `entries_disabled` | 전략 OFF (보유 포지션 관리는 계속) |
| `stale_signal_data_gap` | 신호 봉과 체결 봉 사이에 캔들이 빠져 있음 (거래량 0 구간이 결측 처리된 경우 포함) |
| `stop_on_wrong_side` | 기준가(시가)가 이미 손절가에 닿았거나, 손절가가 슬리피지 폭 안에 있음 |
| `target_passed_at_fill` | 예상 체결가가 이미 목표가를 지남 |
| **`net_rr_below_min`** (0.3.0) | 신호가 `min_rr`을 지정한 경우, **예상 체결가와 예상 비용을 반영한 순손익비**가 그보다 낮음 (§5) |
| Risk Engine | `max_open_positions`, `daily_loss_limit`, `below_min_size`(내림 후 최소 주문 미달), `no_equity` |
| `already_in_position` / `order_pending` | 보유 중이거나 지정가 주문 대기 중 |

- 청산 신호는 결측 뒤에도 실행한다 (보호 목적).

## 3. 손절(SL) / 익절(TP)

| 상황 | 처리 |
|---|---|
| 손절 도달 | SL 가격에 시장가 체결 + 불리한 슬리피지, taker 수수료 |
| 시가가 SL을 갭으로 넘음 | SL이 아니라 **시가**(더 나쁜 가격) |
| 목표 도달 | TP 가격 그대로 (지정가 가정, 슬리피지 없음). 수수료 기본 taker |
| 시가가 TP를 유리하게 넘음 | 더 좋은 시가가 아니라 TP 가격 |
| **같은 봉에서 SL과 TP 모두 도달** | **SL 먼저**로 처리, `ambiguous_bar` 표시 |
| 데이터 끝까지 보유 | 마지막 종가로 강제 청산 (`end_of_data`) |

## 4. 지정가 진입 (0.3.0)

신호가 `limit_price`를 주면 다음 봉부터 `limit_expiry_bars` 동안 주문이 대기한다.

| 규칙 | 내용 | 근거 |
|---|---|---|
| 체결 조건 | 가격이 지정가를 **`limit_fill_penetration_bps`(기본 1bp) 이상 관통**해야 체결. 고가/저가가 지정가에 **닿기만 한 것은 체결이 아니다** | 닿았다고 내 주문 순서까지 체결됐다는 보장이 없음 |
| 체결가 | 항상 지정가. 시가가 지정가를 넘어 열려도 더 좋은 가격을 주지 않음 | 보수적 |
| 수수료 | 기본 taker (`limit_entry_fee: maker`로 변경 가능) | 보수적 |
| 접수 시 검사 | 손절·목표 방향, 지정가 기준 순손익비 ≥ `min_rr` | §5 |
| 미체결 취소 | 만료(`limit_expired`), 데이터 결측(`limit_cancelled_data_gap`), 전략 OFF, **미체결 상태에서 목표가 도달**(`limit_cancelled_target_reached`: 아이디어 무효) | — |
| 체결 후 | **취소 불가.** 포지션은 손절·목표로 관리 | — |
| **체결 봉 안의 순서 불명** | 체결 봉에서 손절가도 범위 안이면 **손절된 것으로 처리**(손실), 목표가가 범위 안이어도 **익절로 인정하지 않음**. 둘 다 `fill_bar_ambiguous` 표시. 익절은 다음 봉부터 인정 | 봉 내부 경로를 모름 → 불리한 쪽 |
| 체결 봉의 유리한 변동 | MFE에 넣지 않음 | 위와 같음 |

`limit_fill_penetration_bps = 0`("닿으면 체결")은 낙관적 가정이며 비교용으로만 쓴다.

## 5. 순손익비 (체결가·비용 반영)

```
손절 체결가   = 손절가 × (1 ± 슬리피지)
단위당 손실   = |손절 체결가 − 진입가| + 진입가×진입 수수료 + 손절 체결가×청산 수수료
단위당 보상   = |목표가 − 진입가| − 진입가×진입 수수료 − 목표가×목표 수수료
순손익비      = 단위당 보상 / 단위당 손실
```
- 진입가 = 시장가는 `다음 시가 ± 슬리피지`, 지정가는 지정가.
- 전략의 자체 검사(신호 봉 종가 기준, 비용 제외)는 그대로 두고, 엔진이 주문 직전에 **한 번 더** 검사한다.
- 손절폭이 좁을수록 비용 비중이 커져 순손익비가 크게 낮아진다. 실측 예: 계획 2.17 → 순 0.13 (손절폭 0.09%).

## 6. 수량 (비용 포함, 0.3.0)

```
위험 예산 = 실현 자산 × risk_per_trade_pct (기본 0.25%)
수량     = 위험 예산 / 단위당 손실        ← §5의 손실 (손절 손실 + 진입·청산 수수료 + 손절 슬리피지)
```
- OKX BTC-USDT-SWAP: 1계약 = 0.01 BTC, 주문 단위 0.01계약 → **0.0001 BTC 단위로 내림** (올림 없음).
- 내림 후 최소 주문(0.01계약)에 못 미치면 **진입 거부** (`below_min_size`).
- 명목가치가 `자산 × max_leverage`(기본 3배)를 넘으면 수량 축소.
- 결과: 정상 손절 시 손실이 예산과 거의 같다 (`r_multiple ≈ −1`). `r_multiple = 순손익 / 위험 예산`.
- 포함하지 않는 것: 펀딩(보유 기간을 미리 알 수 없음), 손절가를 갭으로 넘는 추가 손실.
- 일일 손실 한도(기본 1%, 실현 손익 기준), 동시 포지션 1개.
- **증거금·강제 청산은 모델링하지 않는다.**

## 7. 비용 가정

| 항목 | 기본값 | 비고 |
|---|---|---|
| Taker / Maker 수수료 | 0.05% / 0.02% | 수수료 등급에 따라 다름 (가정) |
| 슬리피지 | 2 bps | 시장가 체결에만, 불리한 방향 (가정) |
| **펀딩** | 8시간당 0.01%, **방향과 무관하게 비용** | **실측값이 아닌 가정.** OKX는 최근 약 94일의 요율만 제공 (2026-08-10 이후 실측 평균 +0.0058%, 범위 −0.0047%~+0.01%, 음수 7.8%) |

펀딩 모드: `cost`(기본: 항상 비용) / `signed`(요율 > 0이면 롱이 내고 **숏이 받음**, 음수 허용).
민감도 분석: `services/sensitivity.funding_sensitivity` — 무펀딩, 0.01%/0.03%/0.05% 비용, 부호 반영 +0.0058%/+0.01%/−0.01% 시나리오로 같은 신호를 다시 계산한다.

## 8. 데이터 규칙
- 미완성 캔들 미사용. 결측은 채우지 않는다.
- **거래량 0 연속 구간**: 30분 이상(5m 6봉)이면 결측으로 취급해 제거 → 그 구간을 포함한 상위 봉 폐기, 스윙·FVG 불성립, 직후 진입 거부. 1~5봉 구간은 유지하되 실행 기록에 플래그로 남긴다.
- **OOS 봉인**: `config/research_split.yaml`의 OOS 구간과 겹치는 기간은 백테스트·Inspector·연구 차트·감사 모두 거부 (API·CLI·UI 공통).
