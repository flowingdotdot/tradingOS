# 백테스트 체결 모델 (Backtest Execution Model)

> 엔진 버전 **0.2.0** (`backend/src/tradingos/backtest/engine.py`). 2026-11-11 검토.
> 이 문서는 엔진이 **실제로 하는 일**만 적는다. 구현되지 않은 것은 §8에 "미지원"으로 따로 적는다.
> 모든 결과는 가정에 기반한 가상 시뮬레이션이며 미래 성과를 보장하지 않는다.

## 1. 한 봉의 처리 순서

봉 i (시작 시각 `ts_i`)에서 다음 순서로 처리한다.

| 순서 | 처리 | 가격 |
|---|---|---|
| 1 | 펀딩: 이전 봉에서 넘어온 포지션이 `(ts_{i−1}, ts_i]` 사이의 펀딩 시각(00/08/16 UTC)을 지나면 차감 | 명목가치 = 수량 × 봉 i 시가 |
| 2 | 봉 i−1 종가에서 결정된 **청산 신호** 실행 | 봉 i 시가 ± 슬리피지 |
| 3 | 봉 i−1 종가에서 결정된 **진입 신호** 실행 (사전 검사 → Risk Engine → 체결) | 봉 i 시가 ± 슬리피지 |
| 4 | 봉 i의 고가/저가로 손절·목표 도달 검사 (방금 진입한 포지션 포함) | §3 |
| 5 | 봉 i 종가에서 신호를 읽어 봉 i+1에 실행할 행동 예약 | — |
| 6 | 자산 평가 (실현 자산 + 미실현 손익, 봉 i 종가 기준) | — |

## 2. 신호 봉과 체결 봉 (Market Order)

- 전략은 봉 i가 **닫힌 뒤** 그 봉까지의 데이터로 신호를 낸다. 체결은 **봉 i+1의 시가**다. 신호 봉 종가에 체결되는 일은 없다.
- 시장가 체결가 = `시가 × (1 + 슬리피지 × 방향)` — 롱은 더 비싸게, 숏은 더 싸게(불리하게).
- 마지막 봉의 신호는 실행되지 않는다 (다음 시가가 없음).
- **진입 사전 검사 (하나라도 걸리면 진입 거부, 사유 기록):**

| 사유 | 조건 | 도입 |
|---|---|---|
| `stale_signal_data_gap` | 신호 봉과 체결 봉 사이에 캔들이 빠져 있음 (`ts_i − ts_{i−1} ≠ 봉 길이`). 오래된 신호를 몇 시간 뒤 가격에 체결하지 않는다 | 0.2.0 |
| `stop_on_wrong_side` | 시가가 이미 손절가에 닿았거나 넘음 (손절가가 시가와 체결가 사이, 즉 슬리피지 폭 안에 있는 경우 포함) | 0.2.0에서 강화 |
| `target_passed_at_fill` | 체결가가 이미 목표가를 지남. 0.1.0은 목표를 조용히 지우고 포지션을 유지했다 (결함) | 0.2.0 |
| `entries_disabled` | 전략 OFF (신규 진입만 차단; 보유 포지션 관리는 계속) | — |
| Risk Engine 거부 | `max_open_positions`, `daily_loss_limit`, `stop_on_wrong_side`(체결가 기준), `below_min_size`, `no_equity` | — |
| `already_in_position` | 보유 중 같은 방향 신호 (추가 진입·물타기 없음) | — |

- 청산 신호는 결측 뒤에도 **실행한다** (보호 목적: 첫 번째로 존재하는 시가).

## 3. 손절(SL) / 익절(TP)

| 상황 | 처리 |
|---|---|
| 손절 도달 (롱: 저가 ≤ SL, 숏: 고가 ≥ SL) | SL 가격에 시장가 체결 + 불리한 슬리피지, taker 수수료 |
| 시가가 SL을 갭으로 넘음 | SL이 아니라 **시가**(더 나쁜 가격) + 슬리피지 |
| 목표 도달 (롱: 고가 ≥ TP, 숏: 저가 ≤ TP) | TP 가격 그대로 체결 (지정가 가정, 슬리피지 없음). 수수료는 기본 taker (`target_fill_as_maker=true`면 maker) |
| 시가가 TP를 유리하게 넘음 | 더 좋은 시가가 아니라 **TP 가격** (보수적) |
| **같은 봉에서 SL과 TP 모두 도달** | **SL 먼저**로 처리하고 거래에 `ambiguous_bar` 표시. 봉 내부의 실제 순서는 알 수 없다 |
| 진입한 봉에서 SL/TP 도달 | 검사한다 (시가 진입 후의 움직임이므로) |
| 데이터 끝까지 보유 | 마지막 종가 + 슬리피지로 강제 청산 (`end_of_data`) |

## 4. 수수료·슬리피지·펀딩

| 항목 | 기본값 | 적용 |
|---|---|---|
| Taker 수수료 | 0.05% | 모든 시장가 체결의 명목가치 (진입·손절·신호 청산·강제 청산) |
| Maker 수수료 | 0.02% | `target_fill_as_maker=true`일 때 TP 체결에만 |
| 슬리피지 | 2 bps | 시장가 체결에 불리한 방향. TP에는 없음 |
| 펀딩 | 8시간당 0.01% **고정 가정** | 펀딩 시각을 넘긴 포지션에 **방향과 무관하게 비용**으로 차감 |

- 수수료 등급·실제 스프레드에 따라 달라진다. 기본값은 가정이다.
- **펀딩은 단순화 모델이다.** 실제 펀딩은 요율이 매번 다르고 방향에 따라 받기도 한다. 실제 과거 요율은 반영하지 않는다 (§8).
- 가격은 호가 단위(0.1)로 반올림하지 않는다 (슬리피지 적용 후 가격이 0.1 단위가 아닐 수 있음). 영향은 1bp 미만.

## 5. 수량·계약·손익

- BTC-USDT-SWAP: 1계약 = 0.01 BTC, 주문 단위 0.01계약 → 최소 증분 **0.0001 BTC**. 수량은 항상 **내림**한다.
- 손익(USDT 선형 계약): `(청산가 − 진입가) × 방향 × 수량(BTC)`.
- `net_pnl = gross_pnl − 수수료 − 펀딩`. 슬리피지는 체결가에 이미 들어 있으므로 `gross_pnl`에 포함된다 (`slippage_cost`는 참고용 분해값).
- `r_multiple = net_pnl / risk_amount`, `risk_amount = 수량 × |체결가 − 손절가|` (비용 제외 계획 손실).

## 6. 포지션 크기·레버리지·증거금

- 수량 = `실현 자산 × risk_per_trade_pct / |체결가 − 손절가|`. 기본 0.25%.
- 명목가치가 `자산 × max_leverage`(기본 3배)를 넘으면 수량을 줄인다 (`capped_by_leverage`).
- 일일 손실 한도(기본 1%): 그날(UTC) **실현** 손익이 한도에 닿으면 신규 진입 차단. 미실현 손익은 보지 않는다.
- 동시 포지션 1개.
- **증거금·청산(강제 청산)은 모델링하지 않는다.** 레버리지 상한은 명목가치 제한일 뿐이다. 3배에서 강제 청산은 약 33% 역행이 필요하고 손절이 훨씬 가까우므로 현재 설정에서는 실질 영향이 없지만, 손절 없는 전략이나 높은 레버리지에서는 결과가 낙관적으로 나온다.

### ⚠ 알려진 한계: 리스크 예산은 비용을 포함하지 않는다
수량은 손절폭만으로 정한다. 손절폭이 매우 좁으면 수량(명목가치)이 커져 **수수료·슬리피지가 계획 리스크보다 커질 수 있다.**
실측 (ICT v1-mss-close 150일, 거래 #2): 손절폭 55 USDT (0.09%) → 명목가치 28,333 USDT (2.8배) → 수수료 28.35 + 슬리피지 11.34 USDT vs 계획 리스크 24.92 USDT → 실현 **−2.37R** (자산의 0.59%, 한도 0.25%의 2.4배).
이것은 계산 오류가 아니라 정책의 한계다. 대응 방안(비용 포함 사이징, 최소 손절폭)은 결과를 바꾸는 정책 결정이므로 임의로 적용하지 않았다 — [strategies/ict_ote.md](strategies/ict_ote.md) §11 참조.

## 7. 계획 손익비와 체결가
전략의 최소 손익비 검사는 **신호 봉 종가** 기준이다. 실제 체결은 다음 봉 시가 ± 슬리피지이므로 체결가 기준 손익비는 더 낮을 수 있다.
실측: 4건 중 2건이 체결가 기준 1.5 미만 (1.45, 1.39). 엔진은 체결가 기준 손익비를 다시 검사하지 않는다 (`GET /api/backtests/{id}/audit`가 두 값을 모두 보여준다).

## 8. 지원 여부 요약

| 기능 | 상태 |
|---|---|
| 시장가 진입 (다음 봉 시가) | ✅ 지원 |
| 손절 / 목표 / 신호 청산 | ✅ 지원 |
| 수수료, 슬리피지 | ✅ 지원 (고정 비율 가정) |
| 펀딩 | ⚠ 단순화 (고정 요율, 항상 비용). **실제 과거 펀딩 요율 미지원** |
| 리스크 기반 수량, 레버리지 상한, 일일 손실 한도 | ✅ 지원 |
| **지정가(Limit) 진입** | ❌ **미지원.** 지정가 신호가 있으면 엔진과 백테스트 API가 실행을 거부한다 (`v1-fvg-retest`는 백테스트 불가) |
| 부분 체결, 호가 잔량, 체결 지연 | ❌ 미지원 (전량 즉시 체결 가정) |
| 증거금, 강제 청산 | ❌ 미지원 |
| 봉 내부 가격 경로 | ❌ 미지원 (OHLC만 사용; SL/TP 동시 도달 시 SL 우선) |
| 체결가 기준 최소 손익비 재검사 | ❌ 미지원 |
| 비용을 포함한 수량 계산 | ❌ 미지원 |
| 다중 포지션 / 포트폴리오 시뮬레이션 | ❌ 미지원 (포지션 1개) |
| 호가 단위 가격 반올림 | ❌ 미지원 |
