# Trading OS — Investment Intelligence 명세 (Track B)

> 상태: v0.1 **설계 단계, 미구현.** 단기 자동매매(Track A: Strategy/Backtest/Trading Desk)와 **독립된** 워크스페이스.
> 산출물은 **연구와 추천**뿐이다. 주문 실행은 범위 밖이며, 향후 별도 구현 + 지원되는 브로커 연동 + 사용자의 명시적 승인이 있어야만 가능하다.

## 1. 목적과 경계

| 구분 | 내용 | 실행 권한 |
|---|---|---|
| 교육용 리서치 (Research) | 지표 해설, 시장 간 관계, 시나리오 | 없음 |
| 투자 추천 (Recommendation) | 제약 조건 하의 자산배분 후보 + 근거·반론·무효화 조건 | 없음 |
| 주문 실행 (Execution) | **이 워크스페이스에 없음.** Track A와도 연결하지 않음 | — |

Track A와의 공유: 저장소/설정/로깅/감사 인프라, 차트 컴포넌트, 재현성 메타데이터 규약. **공유하지 않음:** 실행 엔진, 거래소 자격증명.

## 2. 연구 유니버스와 데이터 출처 (후보)

| 대상 | 후보 출처 | 비고 |
|---|---|---|
| 미 국채 2Y/10Y 수익률, T-bill | FRED (`DGS2`, `DGS10`, `DTB3`) | 일간 |
| 인플레이션 (CPI, PCE), 고용 (NFP, 실업률), 성장 (GDP) | FRED / **ALFRED** (빈티지) | **개정(revision)됨 → 빈티지 필수** |
| 연준 정책금리, 대차대조표(유동성) | FRED (`DFF`, `WALCL`), FOMC 일정 | 결정 시각 기록 |
| 달러지수 | FRED `DTWEXBGS`(광의 달러지수) 또는 라이선스 데이터 | ICE DXY 자체는 라이선스 필요 |
| VIX | FRED `VIXCLS` (CBOE 원천) | |
| S&P 500, Nasdaq 100 | FRED `SP500`, `NASDAQ100` (이용약관·이력 길이 확인 필요) / 라이선스 데이터 | 배당 포함 총수익은 별도 출처 필요 |
| 금 | 라이선스 데이터 또는 ETF 가격 | LBMA 가격은 이용 제약 확인 필요 |
| BTC, ETH | OKX (Track A 데이터 엔진 재사용) | |
| 시장 컨센서스(예상치) | **무료 신뢰 출처가 제한적** — 라이선스 필요 가능성 높음 | 결정 필요 (§8) |

모든 데이터 행은 `source, series_id, observation_date, value, realtime_start(공표/빈티지 시각), retrieved_at` 을 갖는다.

## 3. 연구 무결성 — Point-in-Time 원칙 (가장 중요)

백테스트의 look-ahead와 같은 문제가 거시 데이터에서는 더 교묘하다.

1. **발표 지연**: 3월 CPI는 4월 중순에 발표된다. 3월 31일 시점의 의사결정은 3월 CPI를 알 수 없다. → 모든 관측치에 **공표 시각(knowledge time)** 을 저장하고, 의사결정 시점 `t`에는 `공표시각 ≤ t` 인 값만 사용.
2. **개정(revision)**: GDP·고용은 여러 번 수정된다. 오늘 FRED에서 받은 과거 값은 *당시엔 아무도 몰랐던* 최종 수정치다. → ALFRED **빈티지**를 저장하고, 시점 `t`의 "당시 최신 빈티지"만 사용.
3. **예상치(컨센서스)**: 서프라이즈(실제−예상) 분석에는 발표 *직전* 예상치가 필요. 사후 수정된 예상치 사용 금지.
4. **생존 편향/지수 구성 변경**: 지수 수준 데이터 사용, 개별 종목 유니버스는 범위 밖.
5. 데이터 저장 모델: `(series_id, observation_date, realtime_start, realtime_end, value)` — 쿼리 API는 `as_of(t)` 를 필수 인자로 받는다 (기본값 "지금"을 두지 않는다 → 실수로 미래 데이터 사용 방지).

검증 테스트: Track A의 인과성 검사와 같은 방식으로, `as_of(t)` 결과가 `t` 이후 공표/개정을 추가해도 변하지 않음을 테스트한다.

## 4. 분석 모듈 (계획)

- **레짐 지표**: 성장(↑/↓) × 인플레이션(↑/↓) 4분면, 금융여건(신용스프레드, VIX, 달러, 실질금리), 유동성(연준 대차대조표, 역레포, TGA).
- **시장 간 관계**: 롤링 상관/베타 + **불안정성 표시** (상관의 신뢰구간, 레짐별 차이). 상관은 "관측된 경향"으로만 표기.
- **시나리오**: 명시적 가정(예: "향후 6개월 근원 PCE 3% 유지, 연준 동결")을 입력으로, 자산별 영향 방향과 근거를 구조화. 각 시나리오에 **반대 증거와 무효화 조건** 필수.
- **랭킹 모델**: 설정 가능한 가중치의 설명 가능한 점수(예: 밸류에이션, 모멘텀, 캐리, 레짐 적합도, 변동성 조정). 각 점수의 기여도를 분해해 표시. **현금/미투자 선택지가 항상 후보에 포함.**
- **포트폴리오 비교**: 기대수익(가정 명시), 변동성, 최대낙폭, 상관, 유동성, 통화 노출을 후보 배분안별로 비교. 과거 시뮬레이션은 §3 원칙 준수.

## 5. 사용자 제약 조건

투자 자본, 투자 기간, 위험 허용도, 최대 허용 낙폭, 통화·국가 노출 한도, 유동성 요구(언제 얼마를 현금화해야 하는가). 제약을 위반하는 후보는 순위에서 제외하고 **제외 사유를 표시**한다.

## 6. 추천 기록과 사후 평가

- 모든 추천은 불변 레코드: `rec_id, created_at, as_of, model_version, data_snapshot_ids, constraints, candidates+scores, chosen, rationale, counterarguments, invalidation_conditions, review_date`.
- 사후 평가: 리뷰 시점에 실제 결과를 기록하고 **현금 대비/단순 벤치마크 대비** 성과를 비교. 좋은 결과와 좋은 결정을 구분하기 위해 당시 근거도 함께 보존.

## 7. AI 리서치 어시스턴트 (선택 기능)

허용: 요약, 시장 간 관계 설명, 가설 제안, 시나리오 비교, 상충 증거 식별, 보고서 초안.

강제 규칙 (구조로 보장):
1. **데이터 날조 금지**: LLM은 수치를 생성하지 않는다. 모든 수치는 도구 호출로 시스템 DB에서 가져오며, 보고서의 각 수치는 `series_id + as_of` 인용을 가진다. 인용 없는 수치는 렌더링 단계에서 거부/표시.
2. **확률 표현 제한**: 보정되지 않은 신뢰도 점수를 확률로 표시하지 않는다 ("높음/중간/낮음 + 근거"). 보정된 모델이 생기면 그 출처를 명시.
3. **상관 ≠ 인과**: 역사적 관계는 "관측된 경향, 레짐 의존" 문구 + 반례 기간 표시.
4. **실행 권한 없음**: 어시스턴트에 주문/리밸런싱 도구를 제공하지 않는다. 리스크 한도·결정론적 규칙을 변경하는 도구도 제공하지 않는다.
5. 모델 ID, 프롬프트 버전, 사용한 데이터 스냅샷을 보고서와 함께 저장 (재현성).

## 8. 결정 필요 (Open Questions)

1. 주식지수·금·DXY·컨센서스 데이터의 **라이선스 출처**를 무엇으로 할지 (무료 출처는 범위·이력·이용약관 제약).
2. 기준 통화: USD vs KRW (통화 노출 계산과 성과 측정 기준이 달라짐).
3. 리밸런싱 주기와 시뮬레이션 단위 (월간 권장).
4. LLM 사용 여부/공급자, 그리고 외부 전송 가능한 데이터 범위 (개인 자산 정보 포함 여부).

## 9. 단계 (Track B 로드맵)

- **B1 데이터**: FRED/ALFRED 클라이언트 (API 키는 환경변수), point-in-time 저장소, `as_of` 쿼리, 인과성 테스트.
- **B2 대시보드**: 레짐 지표, 수익률 곡선(2s10s), 금융여건, 자산 간 롤링 상관 (불안정성 표시).
- **B3 시나리오 & 랭킹**: 설정 가능한 설명형 점수, 현금 대안, 제약 조건 필터.
- **B4 포트폴리오 연구**: point-in-time 월간 배분 시뮬레이션, 비교 지표.
- **B5 추천 기록 & 리포트**: 불변 추천 레코드, 사후 평가.
- **B6 AI 어시스턴트 (선택)**: 인용 강제 도구 기반 설계.

Track A Phase 2–4를 우선하고, B1은 Track A Phase 3 이후 병행을 권장한다 (이유: 공유 인프라 — 저장소, 재현성 규약, 차트 — 가 그때 안정화됨).
